## Ringoo — инструкции для AI-агента (Cursor)

### Цель

Делать изменения так, чтобы связка **Django/DRF + Next.js** оставалась целостной: кнопки → правильные endpoint’ы, состояния UI → данные сервера, без потери корзины/заказов.

### Как работать в этом репозитории

- **Сначала найти существующий паттерн**, потом расширять. Не плодить параллельные “вторые” API-клиенты/хуки/сервисы.
- Любая правка в `auth/cart/orders` считается высокорисковой: проверяй ключевые сценарии из `docs/FRONTEND_BACKEND_INTEGRATION_AUDIT.md`.
- Если меняется API контракт — синхронизируй:
  - `backend` (serializer/view)
  - `frontend/src/lib/api/services`
  - `frontend/src/types`
  - `docs/API.md` (и/или OpenAPI)

### Качество изменений

- **Ошибки**: UI должен показывать понятное сообщение (через `getFriendlyErrorMessage`), без “white screen”.
- **Загрузка**: всегда есть loading/skeleton и блокировка повторного submit.
- **Кэш**: после мутаций — корректная инвалидация TanStack Query ключей.
- **Безопасность**: не коммитить `.env`, не помещать приватные ключи в `NEXT_PUBLIC_*`.
