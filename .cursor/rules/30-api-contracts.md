## Контракты API (DRF ↔ Frontend)

### Источник правды

- **Факт**: сериализаторы/вьюхи бэкенда определяют реальный контракт.
- **Обязательство**: фронт типы и сервисы должны соответствовать факту.

### Правило “одно изменение — три места”

Если меняешь:
- endpoint / метод / query params / поля ответа → обнови:
  - `frontend/src/lib/api/services/*`
  - `frontend/src/types/*`
  - `docs/API.md` (и/или OpenAPI, если включено)

### Совместимость и миграции

- Не ломай контракт без версии или явного плана миграции.
- Если нужно временно отключить endpoint (как `bonus/`), обнови документацию и убедись, что фронт не вызывает его.

### Идемпотентность и кэш

- Для операций, которые пользователь может повторить (создание заказа, оплата, обновления) — обеспечь идемпотентность.
- Любое кэширование на бэке должно учитывать query params и пагинацию.
