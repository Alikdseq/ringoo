## Тестирование и регрессии интеграции

### Минимальный набор сценариев (must-pass)

- **Cart guest → login**: гость добавил товары → логин → корзина сохранена/слита.
- **Create order**: заказ создаётся с idempotency key; повтор POST с тем же ключом не дублирует.
- **After order**: корзина очищается, заказы обновляются в ЛК.
- **401 → refresh → retry**: запрос повторяется после refresh без ручных действий пользователя.
- **429 UX**: при throttling пользователь видит понятное сообщение.

### Принципы

- Каждый критичный баг → тест, который воспроизводит баг.
- Фронт тесты должны мокать API в формате, совпадающем с DRF (MSW/моки).
