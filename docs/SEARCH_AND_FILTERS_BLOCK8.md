# Блок 8: Поиск и фильтрация (масштабирование)

Документ фиксирует решения по поиску, фильтрам и данным каталога (Доработки.md, блок 8).

---

## 8.1 Оценка и план внедрения поиска

### Текущий поиск (PostgreSQL)

- **Объём каталога:** до **~10 000 активных товаров** текущего поиска по БД достаточно.
- **Реализация:** `GET /api/v1/products/products/` с параметрами:
  - `search` — поиск по полям `title` и `sku` (ILIKE/icontains);
  - `category` — фильтр по slug категории;
  - `min_price`, `max_price` — диапазон цен;
  - `in_stock` — только товары в наличии (подзапрос по Stock, available_quantity > 0);
  - `ordering` — сортировка (price_asc, price_desc, rating_desc, created_at).
- **Автодополнение:** `GET /api/v1/products/autocomplete/?q=...` — до 10 товаров по title/sku.

### Когда переходить на Elasticsearch/OpenSearch

- **Рекомендуемый порог:** **>10 000 товаров** или потребность в:
  - полнотекстовом поиске с морфологией и релевантностью;
  - поиске по описанию, характеристикам, бренду;
  - фасетам (агрегации по категориям/брендам для фильтров);
  - высокой нагрузке на поисковые запросы.
- До этого порога оставлять поиск по PostgreSQL (title, sku, фильтр in_stock) — без внедрения отдельного движка.

### План миграции на поисковый движок

1. **Подготовка:** выбор движка (Elasticsearch или OpenSearch), развёртывание кластера/сервиса.
2. **Индексация:** скрипт/задача синхронизации Product (и при необходимости Category, Stock) в индекс; обновление при изменении товаров (сигналы Django или периодическая переиндексация).
3. **Backend:** новый сервис поиска (по индексу), сохранение текущего GET-эндпоинта списка товаров; переключение логики списка на поисковый бэкенд по feature-flag или по числу товаров в БД.
4. **Фронт:** без изменений API контракта (те же query-параметры и структура ответа), при необходимости добавить подсказки (suggest) и фасеты из ответа поиска.
5. **Откат:** при проблемах — переключение обратно на выборку из PostgreSQL.

## 8.2 Фильтры (текущая реализация)

- **Диапазон цен:** `min_price`, `max_price` — реализованы на бэкенде и фронте.
- **В наличии:** параметр `in_stock=true` на бэкенде; на фронте — чекбокс/чип «В наличии» в каталоге.
- **Категория:** один выбор (slug) — реализован; мультивыбор категорий или брендов при появлении требований — расширить API (например, `categories=slug1,slug2` или `brand=id1,id2`) и UI (чекбоксы/чипы).

## 8.3 Динамические цены и остатки

- **Остатки:** отдаются из БД (модель Stock, связь с Product). В списке товаров остатки не включены; в карточке товара — через детальный эндпоинт (stock/stock_items).
- **Цены:** из модели Product; изменение цен — через админку/импорт, без персональных правил в текущей реализации.
- **Кэш:** список товаров кэшируется на бэкенде (короткий TTL, см. `CACHE_TIMEOUT_PRODUCTS_LIST`); при необходимости для критичных страниц можно уменьшить TTL или отключить кэш для актуальных цен/остатков.
- **Группы пользователей и персональные цены:** отдельная задача при появлении требований; не входят в текущий блок.
