# План: единый шаблон страницы товара с динамическими данными

## Текущее состояние

- **Маршрут:** один — `app/products/[slug]/page.tsx`, slug динамический.
- **Данные:** товар загружается по slug через `useProduct(slug)` → `getProductDetail(slug)`; один и тот же шаблон (`ProductContent`) получает объект `product: ProductDetail` и рендерит его.
- **Уже динамически:** название, описание, цена, категория, галерея, характеристики (specs), наличие, магазины, табы (описание из product).

## Что было не шаблонным (хардкод)

1. **Блок «Материал»** — три фиксированные кнопки («Кожа Horween», «Кожа», «DuraBack»), не привязаны к данным товара.
2. **Блок «Цвет»** — фиксированные «Черный»/«Коричневый» и свотчи, не из API.
3. **Заголовок вкладки браузера** — не меняется при переходе на товар (остаётся общий «Ringoo»).

Бэкенд отдаёт для товара массив **specs** (пары name/value). В тестах уже есть пример: `name: "Цвет", value: "Чёрный"`. Аналогично можно хранить «Материал» и другие варианты в specs.

## План реализации

| Шаг | Задача | Результат |
|-----|--------|-----------|
| 1 | Описать план в документе | Этот файл. |
| 2 | Хелпер для получения значений из `product.specs` по имени (например «Материал», «Цвет»), с учётом нескольких значений. | Функция `getSpecValues(product, name): string[]` (или одна строка). |
| 3 | Блок «Материал»: рендерить варианты из specs; если нет спецификации «Материал» — блок не показывать. | Один шаблон, данные только из product. |
| 4 | Блок «Цвет»: рендерить значение из specs; если нет «Цвет» — блок не показывать. | Один шаблон, данные только из product. |
| 5 | При загрузке товара выставлять `document.title` (и при желании meta description) из данных товара; при уходе со страницы — восстанавливать. | У каждой страницы товара свой заголовок. |

После выполнения страница товара будет единым шаблоном с подстановкой всех отображаемых данных из объекта `product` (и констант/глобальных текстов где нужно).
