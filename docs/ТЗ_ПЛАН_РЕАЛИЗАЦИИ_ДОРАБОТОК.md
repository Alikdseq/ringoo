# Атомарный план реализации доработок по ТЗ

Каждый шаг — одна конкретная задача. Вы присылаете номер шага (например: «Шаг 1.1» или «Выполни 2.3») — выполняю только его.

Основа: **`docs/ТЗ_СПИСОК_ДОРАБОТОК.md`** и **`ТЗ.txt`**. Не менять то, что уже работает.

---

## Раздел A: Главная страница и поиск

| Шаг | Задача | Детали |
|-----|--------|--------|
| **A.1** | Главная: блок «Популярные товары» с реальными данными | Заменить PlaceholderBlock на секцию с grid карточек товаров. Запрос к API (например, `getProducts` с лимитом и, при наличии, флагом is_featured или ordering). Использовать существующие ProductCard и CURRENCY_SYMBOL. Кнопка «Смотреть всё» → ссылка на /catalog. |
| **A.2** | Главная: блок акций с реальными данными | Заменить PlaceholderBlock «Акции и спецпредложения» на блок с реальными акциями из API (как на странице /promotions): карточки с таймером, ссылка «Все акции» → /promotions. |
| **A.3** | Поле быстрого поиска с автодополнением в шапке | В Header добавить поле поиска (иконка + input). При вводе (debounce) запрос к GET /api/v1/products/autocomplete/?q=... Выпадающий список результатов (название, цена, ссылка на товар). Клик по результату — переход на /products/[slug]. На мобиле — иконка поиска, по клику открывать панель/модалку с полем и результатами. |

## Раздел B: Каталог и фильтры

| Шаг | Задача | Детали |
|-----|--------|--------|
| **B.1** | Backend: фильтр по бренду в списке товаров | В ProductListView добавить параметр `brand` (или `brands` для мультивыбора). Фильтрация: Product.objects.filter(brand__iexact=...) или brand__in=... Сохранить в ключе кэша списка товаров. |
| **B.2** | Frontend: фильтр по бренду в каталоге | В ProductFilters добавить `brand?: string`. В каталоге: получить список брендов (отдельный endpoint или из агрегата товаров; при отсутствии API — select с брендами из первых N товаров или статичный список). Добавить в сайдбар и в мобильную панель фильтров. Чип активного фильтра «Бренд: X» с возможностью сброса. |

## Раздел E: Форма «Не нашли нужный товар?»

| Шаг | Задача | Детали |
|-----|--------|--------|
| **E.1** | Backend: поле «имя» в заявке на отсутствующий товар | В модель MissingProductRequest добавить поле contact_name (CharField, max_length=255). Миграция. В сериализаторе и админке — отображение contact_name. |
| **E.2** | Frontend: форма «Не нашли нужный товар?» на каталоге | На странице каталога (внизу или в сайдбаре) блок с заголовком «Не нашли нужный товар?» и форма: имя, телефон, название искомого товара (поле с подсказками от GET /products/autocomplete/?q=...), опционально комментарий. Отправка POST на существующий CRM endpoint. Успех/ошибка — сообщение пользователю. |
| **E.3** | Уведомление менеджера при заявке «Не нашли товар» | В задаче send_missing_product_request_to_crm (или в сигнале после сохранения заявки) добавить отправку email менеджеру (MANAGER_EMAIL или аналог) с данными заявки (имя, телефон, название товара). Использовать существующий email_service при наличии. |

## Раздел F: Рейтинг менеджеров и страница «О нас»

| Шаг | Задача | Детали |
|-----|--------|--------|
| **F.1** | Страница «О нас» с рейтингом менеджеров | Создать страницу /about (или /o-nas). Контент: краткий текст о компании, блок «Рейтинг менеджеров» — запрос GET /api/v1/orders/ratings-summary/, отображение средней оценки (звёзды), количества отзывов, последние отзывы (без персональных данных). Добавить ссылку в шапку/футер. |
| **F.2** | Рейтинг менеджеров в ЛК (опционально) | В профиле/ЛК добавить блок «Оцените работу» или «Рейтинг менеджеров» с данными ratings-summary и, при наличии заказов без оценки, кнопкой «Оценить заказ» (переход на форму оценки по order_id). |
| **F.3** | Проверка отправки ссылки на оценку после заказа | Проверить задачу send_order_notifications (или аналог): уходит ли клиенту email/SMS со ссылкой на форму оценки (через 3 дня или после получения заказа). При отсутствии — добавить в шаблон письма/SMS ссылку на страницу оценки (например, /order-rate?order=...&token=... или существующий механизм). |

## Как работать по плану

- Пишете: **«Шаг A.1»**, **«Выполни B.2»**, **«Сделай E.1 и E.2»** — выполняю только указанные шаги.  
- Можно запрашивать несколько шагов подряд.  
- После выполнения шага можно проверить сценарий и перейти к следующему.
