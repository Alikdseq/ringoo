# Безопасность проекта Ringoo

Чек-лист и реализованные меры по безопасности.

---

## 1. Передача данных

| Требование | Статус | Реализация |
|------------|--------|------------|
| **HTTPS (SSL)** | ✅ | В production: `SECURE_SSL_REDIRECT=True`, редирект с HTTP на HTTPS через Django SecurityMiddleware. |
| **HSTS** | ✅ | `SECURE_HSTS_SECONDS=31536000`, `SECURE_HSTS_INCLUDE_SUBDOMAINS`, `SECURE_HSTS_PRELOAD` (production). |
| **TLS 1.2 / 1.3** | ✅ | Настраивается на уровне веб-сервера (Nginx/тракт). Django не управляет версией TLS. |

---

## 2. Защита форм и API

| Требование | Статус | Реализация |
|------------|--------|------------|
| **CSRF-токены** | ✅ | `CsrfViewMiddleware` включён. JWT-эндпоинты (`/auth/token/`, `register`) с `csrf_exempt`, т.к. авторизация по Bearer, не по cookie. Checkout и остальной API используют JWT или сессию (корзина); для state-changing запросов с того же origin CORS + cookie secure. |
| **Валидация на сервере** | ✅ | Все сериализаторы DRF (заказ, корзина, пользователь, адреса) с валидацией; обязательные поля, форматы, проверка остатков и согласия. |
| **Экранирование вывода (XSS)** | ✅ | В шаблонах Django — автоэкранирование. API отдаёт JSON; фронт (React) экранирует при рендере. CSP и прочие заголовки без устаревшего `X-XSS-Protection`. |
| **Подготовленные запросы (SQL-инъекции)** | ✅ | Везде Django ORM; сырых запросов с подстановкой пользовательского ввода нет. |
| **Rate limiting** | ✅ | DRF throttle: общие лимиты (anon/user), повышенные для read-only (anon_read/user_read), отдельно: создание заказа (20/час user, 10/час anon); авторизация — общий user/anon. |

## 3. Пользовательские данные

| Требование | Статус | Реализация |
|------------|--------|------------|
| **Пароли только в хеше** | ✅ | Argon2 (первый в `PASSWORD_HASHERS`), fallback PBKDF2. Зависимость `argon2-cffi`. |
| **PII не в логах** | ✅ | В логах email/телефон маскируются (`config.pii`: `mask_email`, `mask_phone`). Sentry: `before_send` фильтрует `phone`, `email`, `full_name`, `delivery_address` и др. |
| **Согласие и политика** | ✅ | Чекбокс согласия на checkout (обязательный), страница политики конфиденциальности `/docs/privacy`. |
| **Удаление своих данных** | ✅ | `POST /api/v1/auth/delete-account/` с телом `{"confirm": "DELETE_MY_ACCOUNT"}`: обезличивание заказов (ФИО/телефон/email/адрес), анонимизация пользователя, отключение аккаунта, удаление адресов и корзины. |
| **CSRF (cookie JWT)** | ✅ | `JwtCookieCsrfMiddleware`: `X-CSRFToken` + `csrftoken` для мутаций API при HttpOnly JWT. |
| **RBAC Admin API** | ✅ | Группы `ringoo_*`; `python manage.py seed_admin_groups`. |
| **ConsentRecord (152-ФЗ)** | ✅ | IP, версия политики (`POLICY_VERSION`), регистрация и checkout. |

## 4. Платежи

| Требование | Статус | Реализация |
|------------|--------|------------|
| **Провайдер (ЮKassa, CloudPayments, Тинькофф)** | 📋 | Интеграция не реализована. Рекомендация: подключать только через официальные SDK/iframe провайдера, без своих форм ввода карты. |
| **Без своих форм карты** | ✅ | Своих форм ввода карты нет. При интеграции использовать iframe или SDK провайдера. |
| **Подпись запросов (вебхуки)** | 📋 | При подключении платёжки: проверять подпись уведомлений (secret key, HMAC и т.д.) перед изменением статуса заказа. |

---

## 5. Админка

| Требование | Статус | Реализация |
|------------|--------|------------|
| **Доступ по паролю** | ✅ | Django Admin и Admin API: аутентификация по JWT (тот же пользователь с `is_staff=True`). |
| **Двухфакторка (SMS)** | 📋 | Не реализовано. Рекомендация: `django-otp` + SMS или TOTP (Google Authenticator). |
| **Разграничение ролей** | ✅ | `IsStaff`: доступ к Admin API только при `is_staff=True`. Менеджер может менять статус заказа; изменение цен/товаров — через те же эндпоинты (при необходимости можно ввести отдельные права по группам). |
| **Логирование действий** | ✅ | Приложение `apps.audit`: модель `AuditLog` (кто, когда, модель, объект, изменения). Запись при смене статуса заказа и при обновлении товара в Admin API. |

---

## 6. Дополнительно

- **CORS**: только разрешённые домены из `CORS_ALLOWED_ORIGINS` / `CSRF_TRUSTED_ORIGINS` (в production не `*`).
- **Security headers**: `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy`, `Permissions-Policy` (middleware).
- **Sentry**: `send_default_pii=False`, фильтрация чувствительных полей в `before_send`.
