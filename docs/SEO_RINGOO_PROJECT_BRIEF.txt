1. РЕЗЮМЕ ДЛЯ SEO-СПЕЦИАЛИСТА
================================================================================

Ringoo — интернет-магазин и витрина сети магазинов электроники (смартфоны
Apple/Samsung, аксессуары, техника). Основной регион: Северная Осетия —
Алания, Владикавказ и ближайшие города; доставка также по России (СДЭК).

Сайт — современное веб-приложение:
  • Фронтенд: Next.js 15 (App Router), TypeScript, SSR/SSG где настроено
  • Бэкенд: Django REST API (каталог, заказы, контент, магазины)
  • Данные каталога, meta-полей, акций, статей — из API и админ-панели ERP

Ваша задача — вывести проект на профессиональный уровень органического
поиска: семантика, мета-теги, структура, микроразметка, индексация,
локальное SEO, контент, внутренняя перелинковка, аналитика, мониторинг.

Часть технической базы уже заложена (sitemap.xml, robots.txt, meta на
отдельных страницах, поля meta_title/meta_description в БД). Многое требует
доработки: главная без SEO-title, категории через query-параметры, нет
Schema.org, блог/новости — заглушки, в sitemap нет магазинов и категорий.

4. ТЕХНИЧЕСКАЯ АРХИТЕКТУРА (ВАЖНО ДЛЯ SEO)
================================================================================

4.1. Стек
  • Frontend: Next.js 15, App Router, React, Tailwind CSS
  • Backend API: Django REST Framework, PostgreSQL, Redis, Celery
  • Медиа товаров: отдаются с backend (URL API), в prod — HTTPS
  • Карты: Яндекс.Карты API (страницы магазинов)
  • Опционально: Sentry (ошибки), GA / Яндекс.Метрика (env, по умолчанию выкл.)

4.2. Рендеринг и индексация
  • Корневой layout — серверный; lang="ru"
  • Часть страниц — Server Components с export const metadata (хорошо для SEO)
  • Каталог (/catalog) — клиентский компонент CatalogContent: фильтры, товары
    подгружаются с API на клиенте → для SEO критично обеспечить видимый HTML
    (SSR пререндер списка, или статические посадочные категорий)
  • Карточка товара (/products/[slug]):
      - layout.tsx — generateMetadata с fetch API (SSR meta) ✓
      - page.tsx — 'use client': основной контент и дублирующее обновление
        document.title на клиенте → риск рассинхрона; лучше опираться на layout
  • Главная (/), акции (/promotions), рассрочка (/installment) — без отдельного
    metadata в page.tsx (акции и рассрочка — client components)
  • Блог / новости: статьи в sitemap есть, страницы статей — ЗАГЛУШКИ (placeholder)

4.3. Два режима UI (не путать в аналитике)
  • official — основной публичный магазин (для SEO работать с ним)
  • svoi — альтернативный режим (диалоговый UI), может дублировать контент;
    уточнить у разработки, нужно ли закрывать от индексации отдельными правилами

4.4. API и SEO-поля в БД
  Сущности с полями meta_title, meta_description (заполняются в ERP):
    • Товар (Product)
    • Категория (Category)
    • Магазин (Store)
    • Статья блога (Article)
    • Новость (News)

  Публичное API v1 (база для sitemap и страниц):
    /api/v1/products/products/
    /api/v1/products/categories/
    /api/v1/content/articles/
    /api/v1/content/news/
    /api/v1/stores/
    и др.

5. ПРОДАКШЕН-ОКРУЖЕНИЕ И ПЕРЕМЕННЫЕ
================================================================================

Для корректных canonical, sitemap, Open Graph обязательно в production:

  NEXT_PUBLIC_SITE_URL=https://www.<домен-клиента>.ru
    (приоритетнее NEXT_PUBLIC_APP_URL)

  NEXT_PUBLIC_API_V1_URL=https://api.<домен>/api/v1
    (или единый домен с прокси)

  NEXT_PUBLIC_YANDEX_METRICA_ID=<номер счётчика>
  NEXT_PUBLIC_GA_ID=<GA4 measurement id>   (если используется)
  NEXT_PUBLIC_ENABLE_ANALYTICS=true

Проверка после деплоя:
  • https://<домен>/robots.txt
  • https://<домен>/sitemap.xml
  • https://<домен>/site-map (HTML-карта для людей)
  • Редирект /sitemap → /site-map (301) — не путать с sitemap.xml

Файлы реализации:
  frontend/src/lib/site-url.ts      — getSiteUrl(), getApiV1BaseUrl()
  frontend/src/app/sitemap.ts       — динамический sitemap.xml
  frontend/src/app/robots.ts        — robots.txt

6. ПОЛНАЯ КАРТА URL (ПУБЛИЧНЫЕ СТРАНИЦЫ)
================================================================================

Условные обозначения:
  [INDEX] — должна индексироваться
  [NOINDEX] — не индексировать
  [META] — есть metadata в коде
  [CLIENT] — основной контент на клиенте (риск для краулера)
  [STUB] — страница-заглушка, контент не готов

--- Коммерческие и главные ---
/                          [INDEX]  Главная: акции, категории, товары дня,
                                    магазины, отзывы, подписка
                                    [CLIENT] Нет отдельного page metadata → ДОРАБОТАТЬ

/catalog                   [INDEX]  [META] Каталог с фильтрами (?category=, ?brand=,
                                    ?search=, цена, наличие)
                                    [CLIENT] Посадочные категорий — через query, не ЧПУ

/catalog/category/{slug}   → 301 redirect на /catalog?category={slug}
                                    (ЧПУ категории не индексируется отдельным URL)

/products/{slug}           [INDEX]  [META SSR layout] Карточка товара (PDP)
                                    [CLIENT] основной UI

/promotions                [INDEX]  Акции и спецпредложения
                                    [CLIENT] [STUB meta] → ДОРАБОТАТЬ title/description

/installment               [INDEX]  Калькулятор рассрочки 0%
                                    [CLIENT] → ДОРАБОТАТЬ meta

/cart                      [INDEX?] Корзина — обычно noindex (обсудить)
/checkout                  [NOINDEX] Оформление заказа — закрыть от индекса
/wishlist                  [NOINDEX] Избранное — закрыть (личное)

--- Магазины и локальное ---
/stores                    [INDEX]  [META] Список магазинов, карта
/stores/{slug}             [INDEX]  [META generateMetadata] Страница магазина
                                    НЕТ в sitemap.xml сейчас → ДОБАВИТЬ

/staff/{slug}              [INDEX?] Страница сотрудника/менеджера
                                    НЕТ в sitemap → решить нужность в SEO

--- Сервис ---
/order-status              [INDEX]  [META] Проверка заказа по номеру и телефону
/order-rate                [NOINDEX] Оценка заказа (параметры)
/orders, /orders/{id}      [NOINDEX] ЛК заказов (требует авторизации)
/profile                   [NOINDEX] [META robots index:false] Личный кабинет

--- Контент ---
/blog                      [INDEX]  Список статей (проверить готовность UI)
/blog/{slug}               [INDEX]  [STUB] Шаблон статьи — контент из API не выведен
/news                      [INDEX]  Список новостей
/news/{slug}               [INDEX]  [STUB] Аналогично блогу

--- Информационные ---
/about                     [INDEX]  [META] [canonical] О компании, команда, рейтинг
/site-map                  [INDEX]  HTML-карта разделов (не путать с sitemap.xml)

--- Юридические ---
/docs/privacy               [INDEX]  [META] Политика конфиденциальности (152-ФЗ)
/docs/offer                 [INDEX]  [META] Публичная оферта
/docs/requisites            [INDEX]  [META] Реквизиты (ШАБЛОН — заменить данные)

--- Авторизация ---
/login, /register           [NOINDEX] Вход / регистрация

--- Админка (не для SEO) ---
/admin/*                    [NOINDEX] Закрыто в robots: Disallow /admin/

9. ПРОБЕЛЫ И РИСКИ (AS-IS)
================================================================================

КРИТИЧНЫЕ:
  1. Главная без уникальных meta title/description и H1-стратегии
  2. Категории каталога только как /catalog?category=slug — слабые посадочные
     для НЧ/СЧ запросов «купить iphone владикавказ»
  3. Нет микроразметки Product, Offer, BreadcrumbList, Organization, LocalBusiness
  4. PDP частично client-rendered — проверить, что Google/Yandex видят цену,
     наличие, название в исходном HTML
  5. Блог и новости в sitemap, но страницы — заглушки → thin content риск
  6. Шаблонные реквизиты (Москва) vs реальный адрес в Осетии — противоречие NAP

ВЫСОКИЕ:
  7. /promotions, /installment без server metadata
  8. Магазины не в sitemap.xml
  9. Нет canonical на многих страницах (кроме /about)
  10. Дубли title на блоге: «Статья: {slug}» без человекочитаемого заголовка
  11. cart и wishlist в sitemap — спорная ценность
  12. Нет favicon/brand OG image стандарта в документации SEO

СРЕДНИЕ:
  13. Нет пагинации rel=next/prev в каталоге (если много товаров)
  14. Alt-тексты изображений товаров — проверить заполнение в админке
  15. Скорость: тяжёлые изображения, lazy load — Core Web Vitals аудит
  16. Внутренние якоря /#delivery-payment в подвале — слабая перелинковка

10. АТОМАРНЫЙ ПЛАН РАБОТ SEO-СПЕЦИАЛИСТА (ПО БЛОКАМ)
================================================================================

Ниже каждый пункт — отдельная задача с ожидаемым результатом.
Приоритет: P0 (критично) → P1 → P2.

--- БЛОК A. Аудит и стратегия (P0) ---
A.1  Провести технический аудит: Screaming Frog / Sitebulb / Яндекс.Вебмастер /
     Google Search Console (после доступа к домену).
A.2  Собрать семантическое ядро: коммерция (бренд+модель), гео, информационка.
A.3  Кластеризовать запросы по страницам: главная, категории, PDP, магазины,
     акции, сервисные, блог.
A.4  Составить карту посадочных URL (целевое состояние) и согласовать с разработкой.
A.5  Проанализировать конкурентов в выдаче по Владикавказу / Осетии / СКФО.

--- БЛОК B. Техническое SEO (P0–P1) ---
B.1  Проверить индексацию robots.txt и sitemap.xml на прод-домене.
B.2  Дополнить sitemap: /stores/{slug}, решение по /installment, убрать /cart,
     /wishlist при согласовании.
B.3  Настроить canonical для каталога с фильтрами (только category — индекс;
     лишние параметры — noindex или canonical на базовую категорию).
B.4  ТЗ разработке: SSR/SSG для списка товаров в категории (видимый HTML).
B.5  ТЗ: единый компонент SEOHead (title, description, canonical, og:*).
B.6  ТЗ: metadata на главной, /promotions, /installment (server export).
B.7  Проверить 404/410 для удалённых товаров, редиректы при смене slug.
B.8  SSL, редирект http→https, www vs non-www — один канонический хост.
B.9  XML sitemap index при >50k URL (на будущее).
B.10 Логи сервера: мониторинг 5xx на PDP и каталоге.

--- БЛОК C. On-page и контент (P0–P1) ---
C.1  Главная: уникальный Title (до ~60 символов), Description (до ~160), H1.
C.2  Шаблоны Title/Description для: категория, товар, магазин, акция, статья.
C.3  Заполнить meta_title/meta_description в ERP для ТОП-товаров и категорий.
C.4  PDP: уникальные тексты (short + полное описание), FAQ-блок, характеристики.
C.5  Категории: SEO-текст 300–800 слов (сверху или снизу), не переспам.
C.6  /about: усилить E-E-A-T (история, цифры, команда, отзывы).
C.7  Страницы магазинов: уникальные описания, часы работы, фото, схема проезда.
C.8  Юридические страницы: актуальные реквизиты и контакты (снять шаблон).
C.9  Подвал: реальные телефоны, ссылки на соцсети, единый NAP.

--- БЛОК D. Микроразметка Schema.org (P0) ---
D.1  Organization + WebSite (+ SearchAction на поиск, если есть /search).
D.2  Product + Offer на PDP (price, priceCurrency RUB, availability InStock/OutOfStock).
D.3  BreadcrumbList на каталог → категория → товар.
D.4  LocalBusiness / Store на /stores/{slug} (адрес, geo, openingHours).
D.5  ItemList на листингах категорий.
D.6  Article на блоге (когда контент будет готов).
D.7  Валидация: Google Rich Results Test, Яндекс.Валидатор микроразметки.

--- БЛОК E. Локальное SEO (P0–P1) ---
E.1  Яндекс Бизнес / Google Business Profile — карточки на каждый магазин.

F.1  Хлебные крошки на каталоге и PDP (UI + schema).

--- БЛОК G. Контент-маркетинг (P1–P2) ---
G.1  Довести /blog и /news до production: вывод API, даты, автор, обложки.

G.3  Только индексировать готовые статьи; убрать заглушки из sitemap до готовности.
G.4  OG для статей, Article schema, rel=canonical.

--- БЛОК H. Коммерческие факторы и доверие (P1) ---
H.1  Отзывы на товары (если в API) — schema Review/AggregateRating.

11. ТРЕБОВАНИЯ К КОНТЕНТУ ПО ТИПАМ СТРАНИЦ
================================================================================

11.1. Главная (/)
  Title: бренд + гео + ключевое УТП (1–2 ключа)
  H1: один, человекочитаемый (не дублировать title дословно)
  Блоки: акции, категории, товары дня, магазины рядом, рассрочка, отзывы, подписка
  LCP: оптимизировать hero-изображение /fon/fon.jpg

11.2. Категория (/catalog?category={slug})
  Title: «Купить {категория} во Владикавказе — цены, наличие | Ringoo»
  H1: название категории
  Текст: 1–2 абзаца + список преимуществ
  Фильтры: не раздувать индекс параметрами

11.3. Товар (/products/{slug})
  Title: из meta_title или «{Модель} купить во Владикавказе — цена {N} ₽ | Ringoo»
  Description: выгода + наличие + доставка/самовывоз
  H1: полное название товара
  Уникальный текст ≥ 500 знаков, таблица характеристик, фото с alt

11.4. Магазин (/stores/{slug})
  Title/Description: адрес, район, «наличие», часы работы
  H1: «Магазин Ringoo — {адрес/название}»
  CTA: маршрут, телефон, список товаров в наличии в магазине

11.5. Акции (/promotions)
  Title: «Акции и скидки Ringoo — спецпредложения {месяц год}»
  Индексировать активные акции; архивные — noindex или отдельный раздел

11.6. Сервисные
  /order-status — информативный, без переспама ключей «отслеживание заказа»

11.7. Блог / новости
  Человекочитаемый slug (латиница или транслит)
  Title статьи ≠ slug
  Минимум 2000 знаков для информационных статей (ориентир)

12. ТЕХНИЧЕСКОЕ SEO — ЧЕКЛИСТ ПРОФЕССИОНАЛА
================================================================================

[ ] Один канонический домен (https, www или без www)
[ ] robots.txt доступен и корректен
[ ] sitemap.xml в Вебмастере/GSC, без битых URL
[ ] Нет массовых 404 в индексе
[ ] Meta robots на личных/служебных разделах
[ ] Canonical на всех индексируемых страницах
[ ] Title уникален, 50–60 символов, бренд в конце или начале (единый стиль)
[ ] Description уникален, 140–160 символов, CTA
[ ] H1 один на страницу
[ ] Иерархия H2–H3 логична
[ ] Alt у значимых изображений
[ ] Internal links ≤ 3–4 клика до PDP
[ ] Mobile-friendly (адаптив есть)
[ ] Core Web Vitals: LCP, INP, CLS в зелёной зоне
[ ] HTTPS на всех ресурсах, нет mixed content
[ ] hreflang не нужен (ru only)
[ ] Пагинация каталога обработана
[ ] Open Graph + og:image 1200×630
[ ] Favicon 48/32, apple-touch-icon
[ ] JSON-LD без ошибок валидатора
[ ] Логи: нет циклических редиректов

13. E-COMMERCE SEO (ТОВАРЫ, КАТЕГОРИИ, АКЦИИ)
================================================================================

13.1. Фиды (рекомендуется на этапе P1)
  • Yandex Market / Google Merchant — YML или Google Shopping feed из API
  • Поля: id, title, price, availability, link, image_link, brand, category

13.2. Правила для out-of-stock
  • Товар недоступен: оставлять URL, availability OutOfStock, не 404
  • Или soft 404 + noindex — решение зафиксировать письменно

13.3. Дубли
  • Один товар — один URL (slug)
  • Варианты цвета — параметр на PDP, не отдельные URL без необходимости

13.4. Акции
  • Чёткие даты в контенте (совпадают с таймером на сайте)
  • После окончания — убрать из sitemap или страница «архив акций»
