# Отчёт по аудиту и доработкам (чек-лист Must Have)

По результатам проверки кода проекта Ringoo по чек-листу (каталог, фильтры, поиск, корзина, checkout, личный кабинет) выполнены следующие доработки.

---

## 1. Защита от двойной отправки заказа (Checkout)

**Проблема:** Повторное нажатие «Оформить заказ» или повтор запроса могло создать два заказа.

**Решение:**
- **Backend:** В `OrderListCreateView.post()` добавлена поддержка заголовка `X-Idempotency-Key`. При наличии ключа ответ (201 + данные заказа) кэшируется в Redis на 24 часа (`ORDER_IDEMPOTENCY_CACHE_TIMEOUT`). Повторный запрос с тем же ключом возвращает сохранённый ответ без создания нового заказа.
- **Frontend:** При отправке заказа генерируется уникальный ключ (`crypto.randomUUID()` или fallback) и передаётся в заголовке при вызове `createOrder()`. Один и тот же ключ используется при повторной отправке (например, после таймаута).

**Файлы:** `backend/apps/orders/views.py`, `frontend/src/lib/api/services/orders.service.ts`, `frontend/src/app/checkout/page.tsx`.

---

## 2. Проверка остатков при оформлении заказа (доставка)

**Проблема:** При типе доставки «Доставка» остатки по товарам не проверялись; заказ можно было оформить при нулевом наличии.

**Решение:** Перед созданием заказа при `delivery_type == "delivery"` для каждой позиции проверяется суммарное доступное количество по всем магазинам (`Stock`: `quantity - reserved_quantity`). Если по какому-либо товару доступно меньше, чем запрошено, возвращается `400` с кодом `INSUFFICIENT_STOCK` и сообщением вида: «Недостаточно товара «Название» для доставки (доступно: N).»

**Файлы:** `backend/apps/orders/views.py`.

---

## 3. Поиск по описанию товара

**Проблема:** В ТЗ указан поиск по названию, артикулу и описанию; в API поиск шёл только по названию и артикулу.

**Решение:** В фильтр поиска списка товаров и автодополнения добавлено условие `Q(description__icontains=...)`.

**Файлы:** `backend/apps/products/views.py` (ProductListView.get_queryset, ProductAutocompleteView.get).

---

## 4. SEO: meta_title, meta_description и Open Graph

**Проблема:** Поля `meta_title` и `meta_description` были в моделях Category и Product, но не отдавались в API и не использовались на фронте для тегов и Open Graph.

**Решение:**
- **Backend:** В сериализаторы добавлены поля:
  - `CategorySerializer`: `meta_title`, `meta_description`
  - `ProductDetailSerializer` и `ProductListSerializer`: `meta_title`, `meta_description`
- **Frontend:** На странице товара (`/products/[slug]`):
  - В `document.title` используется `meta_title` или `title` продукта.
  - В `<meta name="description">` выводится `meta_description` или краткое/полное описание (до 160 символов).
  - Устанавливаются `og:title` и `og:description` для превью в соцсетях.

**Файлы:** `backend/apps/products/serializers.py`, `frontend/src/app/products/[slug]/page.tsx`, `frontend/src/types/api.ts`.

---

## 5. Статус наличия и кнопка «В корзину»

**Проблема:** В ТЗ требуется, чтобы статус «В наличии / под заказ / нет» отображался и влиял на кнопку «В корзину». Кнопка была активна даже при отсутствии товара.

**Решение:**
- **Backend:** В сериализаторы продукта добавлено вычисляемое поле `availability_status`: `"in_stock"` при наличии хотя бы одного доступного остатка по складам, иначе `"out_of_stock"`. Поле добавлено в `ProductListSerializer` и `ProductDetailSerializer`.
- **Frontend:** На странице товара кнопка «В корзину» при `availability_status === "out_of_stock"` отключена (`disabled`) и подпись заменена на «Нет в наличии». Текст блока наличия унифицирован с этим статусом.

**Файлы:** `backend/apps/products/serializers.py`, `frontend/src/app/products/[slug]/page.tsx`, `frontend/src/types/api.ts`.

---

## 6. Повтор заказа (Личный кабинет)

**Проблема:** В ТЗ указана возможность «Повтор заказа (одной кнопкой)»; такого функционала не было.

**Решение:**
- **Backend:** Добавлен endpoint `POST /api/v1/orders/<uuid:pk>/reorder/` (доступ только владельцу заказа, авторизованный пользователь). Он добавляет все позиции заказа в текущую корзину пользователя (с актуальной ценой товара); неактивные или удалённые товары пропускаются. Ответ — обновлённая корзина (CartSerializer).
- **Frontend:** На странице детали заказа (`/orders/[id]`) добавлена кнопка «Повтор заказа». По нажатию вызывается `reorderOrder(orderId)`, инвалидируется кэш корзины и выполняется переход на `/cart`. Кнопка во время запроса в состоянии loading.

**Файлы:** `backend/apps/orders/views.py` (OrderReorderView), `backend/apps/orders/urls.py`, `frontend/src/lib/api/services/orders.service.ts`, `frontend/src/app/orders/[id]/page.tsx`.

## Что уже соответствовало чек-листу (без изменений)

- Иерархия каталога, slug, хлебные крошки (редирект категории на каталог с фильтром).
- Карточка товара: название, цена, фото, описание, характеристики, кнопка «В корзину» (теперь с учётом наличия).
- Фильтры по атрибутам (AND), отображение выбранных фильтров и снятие по одному.
- Корзина: добавление/удаление/изменение количества, пересчёт, сохранение по сессии/пользователю, слияние при входе, проверка остатков при добавлении (для выбранного магазина).
- Очистка корзины после успешного заказа.
- Checkout: гостевой заказ, поля ФИО/телефон/email/адрес/комментарий, доставка/оплата, согласие на обработку данных, подтверждение и редирект на успех.
- Регистрация/вход (JWT), профиль, адреса доставки, история заказов, отслеживание заказа по номеру и телефону.

## Не реализовано в рамках этой итерации

- **Восстановление пароля:** В чек-листе указано «восстановление пароля»; в проекте нет endpoint’а сброса пароля (email/SMS). Рекомендуется вынести в отдельную задачу (email-ссылка или SMS-код, страницы сброса на фронте).
- **Явный статус «под заказ»:** Сейчас используется только «в наличии» / «нет в наличии» по остаткам. При необходимости можно ввести в модель Product поле `availability_type` (например, in_stock / on_request / out_of_stock) и выводить его в API и на карточке.

## Рекомендации по тестам

В тестах заказов (`apps.orders.tests`) часть падений связана с уже существующими особенностями:
- В тестовых данных не передаётся `consent_personal_data: true`.
- В `CustomUser.objects.create_user()` передаётся `username` в `extra_fields`, тогда как модель сама выставляет `username=phone`, что даёт дублирование аргумента.

Имеет смысл обновить тесты: добавить `consent_personal_data` в payload создания заказа и убрать `username` из вызовов `create_user` в тестах.
