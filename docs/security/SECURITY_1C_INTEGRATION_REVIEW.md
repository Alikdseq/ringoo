# Интеграция 1С УТ11

Дата: 2026-11-07. HTTP к публикации 1С не было. `ONE_C_API_ENABLED` в тестовых настройках выключен.

## Контракт в коде

Клиент `integrations/onec/client.py` ходит только на базовый URL из настроек. Подтверждённые пути: `CatalogFolders/folders`, `CatalogProducts/products`, `SiteRegistration/registrate`, `SiteOrders/orders`, `SiteOrders/orders/cancel`. Авторизация HTTP Basic из `ONE_C_LOGIN` / `ONE_C_PASSWORD`. Таймаут по умолчанию 60 с. Тело ответа обрезается на 20 МиБ. Редирект на другой host блокируется. Входящего маршрута от 1С к сайту нет.

`normalize_onec_base_url` требует окончание `/razrab/hs` и запрещает `/ut11_test/hs`. Частный IP не запрещает: `http://127.0.0.1/razrab/hs/` в прогоне принят. Покупатель этот URL не задаёт (BE-NOTE-06).

Повторы заказов ограничены `ONE_C_ORDER_SYNC_MAX_ATTEMPTS` (по умолчанию 5). Каталоговый beat включается только флагом `ONE_C_CATALOG_SYNC_ENABLED`. Задачи в этом блоке не ставились.

## Разбор XML

Парсер — `defusedxml`. Внешняя сущность `file:///c:/windows/win.ini` отклонена. Пустое количество не пишется как ноль. Неразбираемое количество получает `skip`. Отрицательное количество ошибочно помечается `positive` и уходит в `upsert`, а apply обрезает его до нуля. Отрицательная цена пишется в карточку (INV-001). Дубликаты кода папки планировщик отмечает конфликтом и не молчит. Сущности, которых нет в выгрузке, apply не удаляет.

Dry-run вызывает план и пишет SyncLog, `apply_catalog_import` не вызывает. На прогоне число товаров до и после dry-run совпало.

## Кто запускает apply

`POST` admin dry-run и apply требуют группу `ringoo_catalog`. Apply дополнительно требует `confirm=true` и `ONE_C_API_ENABLED`. Иначе 403 `onec_api_disabled`. Параллельный apply упирается в `cache.add` ключа `onec:catalog:apply_lock` и в запись SyncLog со статусом `running`. В тестовых настройках кэш DummyCache замок не хранит. Redis на сервере не проверялся. Повторный apply после завершения первого разрешён и снова пишет те же остатки: ключ идемпотентности включает количество, то же количество второй раз движение не дублирует.

`probe_connection` при выключенном API сеть не открывает.

## После блока 8

Отрицательная, пустая, нечисловая, слишком большая и излишне точная цена не перезаписывает карточку. Отрицательный, дробный и слишком большой остаток не записывается и не превращается в ноль через `max(0, ...)`. Явная цена `0` и явный остаток `0` по-прежнему допустимы. Плохая строка не блокирует соседнюю корректную. Проверка есть и в плане, и прямо перед записью. Dry-run кладёт в SyncLog код, поле, значение и причину и базу не меняет. Живая 1С не вызывалась.
