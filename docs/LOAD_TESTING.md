# Нагрузочное тестирование

Перед запуском и в проде: сценарии, инструменты и мониторинг.

---

## 1. До запуска

### Нагрузочный тест (1000 одновременных пользователей)

- Используется **k6** (см. скрипт `scripts/load-test-k6.js`).
- Запуск:
  - Указать `BASE_URL` (API или фронт).
  - `k6 run --vus 1000 --duration 5m scripts/load-test-k6.js` — 1000 виртуальных пользователей, 5 минут.
- Цели: процент ошибок < 1%, p95 времени ответа в пределах SLA (например < 2 с для каталога).

### Тест «чёрная пятница» (3–5× нагрузки)

- Тот же скрипт с увеличенными VU и длительностью, например:
  - `--vus 3000 --duration 10m`
  - или отдельный сценарий с пиками (ступенчатое увеличение VU).
- Проверить: очередь Celery не переполняется, заказы не теряются, ответы API не деградируют.

### Очереди и заказы при пике

- Создание заказа: атомарная транзакция в БД + задача в Celery (письмо). При падении воркера задача остаётся в Redis и выполнится после перезапуска.
- Рекомендация: мониторить длину очереди Celery и число failed задач; при росте — увеличить воркеры или лимиты.

### Таймауты внешних API

- Все вызовы к внешним сервисам (SMS, геокодер, почта) ограничены `EXTERNAL_API_TIMEOUT` (по умолчанию 10 с). При недоступности внешнего API запрос не вешает воркер надолго.

---

## 2. Мониторинг после запуска

### Алерты

- **CPU > 80%** (по серверам приложения и воркерам): алерт в системе мониторинга (Prometheus/Grafana, облачный мониторинг).
- **5xx > 1%** от общего числа запросов: алерт (Sentry, метрики веб-сервера или APM).

### Логи ошибок

- **Sentry**: уже подключён; ошибки и трассы приходят в проект. Настроить уведомления (email/Slack) при росте частоты ошибок.
- При использовании Papertrail/CloudWatch и т.п. — направлять туда логи приложения и веб-сервера.

### Метрики (Prometheus + Grafana)

- Рекомендуется собирать:
  - HTTP-запросы: количество, статусы, гистограммы времени ответа по эндпоинтам.
  - Celery: число задач (pending/success/failure), длина очереди.
  - Redis: память, подключения.
  - БД: соединения, медленные запросы (если есть экспортер).
- Дашборды в Grafana: обзор доступности, задержек, ошибок и очередей.

## 3. Запуск k6

Установка: https://k6.io/docs/getting-started/installation/

```bash
# Базовый сценарий: 1000 VU, 5 мин
k6 run --vus 1000 --duration 5m scripts/load-test-k6.js

# С переменной окружения для URL
BASE_URL=https://api.ringoo.ru k6 run --vus 1000 --duration 5m scripts/load-test-k6.js

# «Чёрная пятница»: 3000 VU, 10 мин
k6 run --vus 3000 --duration 10m scripts/load-test-k6.js
```

Результаты выводятся в консоль; при необходимости экспорт в JSON/CSV или в InfluxDB/Grafana через флаги k6.
