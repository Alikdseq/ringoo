# Ringoo — инструкция для владельца магазина

Простые шаги. **Не** меняйте статусы платежей, остатки и заказы напрямую в базе данных.

Секреты и пароли сюда не записываются.

## 1. Сайт открывается?

1. Откройте в браузере `https://ringoo15.store` (или ваш домен).
2. Должна загрузиться главная без ошибки сертификата.
3. Откройте каталог и одну карточку товара.

Если не открывается — раздел 7.

## 2. Сервисы Docker

На VPS (SSH):

```bash
cd /opt/ringoo   # ваш путь
docker compose -f docker-compose.yml -f docker-compose.prod.yml --env-file .env.production ps
```

Ожидается: `web`, `frontend`, `db`, `redis`, `celery`, `celery-beat` — Up (healthy где есть healthcheck).

## 3. Основные ошибки

```bash
docker compose … logs web --tail=100
docker compose … logs celery --tail=100
```

Не публикуйте логи с телефонами/картами в чаты.

## 4. Свободное место

```bash
df -h
docker system df
```

Если свободно &lt; 15% — срочно чистить старые backup-set / docker dangling images (осторожно) и писать разработчику.

## 5–6. Backup

Локальные наборы: каталог `backups/set_YYYYMMDD_HHMMSS/` + файл `MANIFEST.txt` со `status=SUCCESS`.

```bash
ls -lt backups/set_* | head
tail -5 backups/set_*/MANIFEST.txt
```

Успех = свежий set за согласованный срок (рекомендация ≤ 24 ч) и `status=SUCCESS`.
Offsite S3 — только если вы его настроили (`BACKUP_OFFSITE_*`); иначе «копия только на сервере» = риск.

## 7. Сайт не открывается

1. `ps` контейнеров; restart: `docker compose … up -d`
2. `/health/` с сервера: `curl -sS http://127.0.0.1:8000/health/`
3. Caddy/Nginx: `systemctl status caddy` (или nginx)
4. DNS: с телефона/внешнего ПК `ping` / онлайн DNS checker
5. **Нельзя:** `docker compose down -v`, удалять volumes, править БД руками.

Если health unhealthy — разработчику.

## 8. Не работает оформление заказа

1. Повторить на другом браузере / без VPN.
2. Проверить, выбран ли магазин и есть ли товар.
3. Логи `web` на момент ошибки.
4. **Нельзя:** создавать заказ через SQL.

## 9. Ошибка оплаты (онлайн)

Пока live ЮKassa выключена — онлайн не должен предлагаться. Если включили тест:

1. Номер заказа и время.
2. Статус в админке заказов / платежей.
3. Не нажимать «оплатить» много раз подряд без паузы.
4. Спорный статус — разработчику + сверка в личном кабинете ЮKassa (**не** ставить paid руками).

## 10. Статус заказа

Админка → Заказы → номер. Либо кабинет покупателя.

## 11. Оплачен у банка, на сайте нет

1. Не отменять заказ сразу.
2. Сообщить разработчику: номер заказа, время, скрин ЮKassa.
3. Дождаться reconcile/webhook.
4. **Нельзя:** менять статус на «оплачен» в БД.

## 12. Celery остановился

```bash
docker compose … ps celery celery-beat
docker compose … restart celery celery-beat
```

Проверить, что Beat снова Up (резервы/expire).

## 13. Redis / PostgreSQL

Если `db`/`redis` Restarting — логи + место на диске. Не удалять volume. Разработчику.

## 14. Истёк TLS

Caddy обычно продлевает сам. Если браузер ругается — логи Caddy, порты 80/443, DNS. Разработчику при сбое ACME.

## 15. Когда звонить разработчику

- Потеря денег / двойная оплата / paid без товара
- Утечка данных
- Падение БД / потеря диска
- Неуспешный backup &gt; 24–48 ч
- Подозрение на взлом админки

**Нельзя:** отключать MFA админов, выкладывать `.env`, включать live ЮKassa/1С без плана.
