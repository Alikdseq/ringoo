# Производительность и Core Web Vitals

Чек-лист и реализованные меры.

---

## 1. Фронтенд (Core Web Vitals)

| Метрика | Цель | Реализация |
|--------|------|------------|
| **LCP < 2.5 с** | Главная картинка / контент грузится быстро | Приоритет загрузки первого изображения на главной (`ProductCard` с `priority` для первого товара). Шрифты с `display: swap`. Next.js Image с форматами AVIF/WebP и `sizes`. |
| **FID < 100 мс** | Интерфейс отзывчив | Разделение кода (dynamic import для 3D, Swiper). Шрифты не блокируют рендер. |
| **CLS < 0.1** | Ничего не прыгает | Hero с `min-h-[85vh]`. Карточки с фиксированным `aspect-square` для изображений. Резервные размеры под плейсхолдеры. |

### Оптимизация изображений

- **WebP/AVIF**: в `next.config.ts` заданы `formats: ['image/avif', 'image/webp']` — Next.js отдаёт их при поддержке браузером.
- **Lazy loading**: у всех карточек товаров и галерей `loading="lazy"` (у первого товара на главной — `priority`).
- **Responsive sizes**: у `Image` заданы `sizes` (например `(max-width: 640px) 50vw, 33vw, 25vw`) для корректного выбора разрешения.
- **deviceSizes / imageSizes**: настроены в `next.config.ts` под типичные брейкпоинты.

### 3D / WebGL

- **Fallback на слабых устройствах**: в `canUse3D()` отключение 3D при `prefers-reduced-motion: reduce` и при `hardwareConcurrency <= 4`. На главной при `!use3D` показывается статичный блок (градиент + категории), без 3D-сцены.
- Hero и PDP: 3D подгружается через `dynamic(..., { ssr: false })`, чтобы не блокировать первый рендер.

### CSS/JS

- Next.js в production минифицирует JS/CSS и выставляет кэширование.
- Критичный CSS инлайнится; остальное подгружается по мере необходимости.

## 2. Бэкенд и API

| Мера | Статус | Реализация |
|------|--------|------------|
| **Кэширование** | ✅ | Redis (production): список товаров (5 мин), список категорий (10 мин). Инвалидация по сигналам при изменении Product/Category. Сессии в Redis. |
| **Индексы БД** | ✅ | Индексы по slug, category, is_active, created_at (products); order_number, status, user (orders); product/store (stock); и др. |
| **Пагинация** | ✅ | Список товаров: `PageNumberPagination`, `page_size=20`, `max_page_size=100`. Список заказов: 20 на страницу. |
| **Асинхронные задачи** | ✅ | Celery + Redis: отправка писем после заказа, уведомления CRM, SMS. Не блокируют ответ API. |
| **Таймауты внешних API** | ✅ | `EXTERNAL_API_TIMEOUT` (по умолчанию 10 с) используется в геокодере и SMS — запросы не висят бесконечно. |
| **Мониторинг** | ✅ | Sentry: ошибки и трассы. Время ответа можно смотреть в Sentry Performance. |

## 3. Инфраструктура

| Мера | Статус | Рекомендация |
|------|--------|--------------|
| **Балансировка** | 📋 | При нескольких серверах — балансировщик (Nginx/ALB) без сохранения состояния по сессии или с sticky session только для корзины по cookie. |
| **CDN** | 📋 | Статику раздавать через Cloudflare / Vercel Edge. Медиа (если отдаются с бэкенда) — через тот же CDN или отдельный (S3 + CloudFront). |
| **Автомасштабирование** | 📋 | Горизонтальное масштабирование воркеров (Gunicorn/uWSGI) и Celery по метрикам (CPU, длина очереди). |

---

## 4. Рекомендации

- **Preconnect**: в `layout` или на главной добавить `<link rel="preconnect" href={API_ORIGIN} />` для домена API, чтобы раньше открывать соединение.
- **LCP**: если на главной появится отдельная hero-картинка (не 3D), дать ей `priority` и фиксированные размеры.
- **Метрики**: подключить Real User Monitoring (Sentry, Vercel Analytics или аналог) для контроля LCP/FID/CLS в проде.
